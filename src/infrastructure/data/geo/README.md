# shanghai-districts.json 字段说明

上海市 16 个区的行政区界数据，标准 GeoJSON `FeatureCollection`，作为城市实体（`city-shanghai`）的边界主数据。

**文件概况**：16 个 Feature｜3443 个坐标点｜约 139 KB（未压缩）

## 一、在项目中如何流动

```
shanghai-districts.json
  └─ infrastructure/data/campus.js      import 为 city.geojson
       └─ infrastructure/repositories/createCampusRepository.js
            └─ 快照 city：geojson + districtCount（= features.length）
                 └─ app/hooks/useCampus.js → data.city
                      └─ features/scene/Scene.jsx → <City geojson={city?.geojson} />
                           └─ features/scene/models/City.jsx  投影渲染区界体块与区名标签
```

数据层持有、features 层只负责渲染，场景不直接读本目录文件。

## 二、顶层对象

| 名称       | 类型             | 含义                                                              |
| ---------- | ---------------- | ----------------------------------------------------------------- |
| `type`     | `string`         | 固定为 `"FeatureCollection"`，声明这是要素集合，代码按此校验      |
| `features` | `Array<Feature>` | 16 个区，一个区一条要素；`length` 即快照中的 `city.districtCount` |

## 三、Feature（要素）

| 名称         | 类型     | 含义                                           |
| ------------ | -------- | ---------------------------------------------- |
| `type`       | `string` | 固定为 `"Feature"`                             |
| `properties` | `Object` | 区的属性信息（名称、编码、定位点等），见第四节 |
| `geometry`   | `Object` | 区的几何边界，见第五节                         |

## 四、properties 字段

| 名称              | 类型         | 含义                                                                                | 代码中的用途                                                                                                  |
| ----------------- | ------------ | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `adcode`          | `number`     | 国家行政区划编码（6 位），区的唯一标识。上海各区均为 `3101xx` / `310120` / `310151` | **使用**：要素列表的 React `key`，保证重渲染时 diff 稳定（`City.jsx`）                                        |
| `name`            | `string`     | 区名，如 `浦东新区`、`黄浦区`                                                       | **使用**：三维组的 `name`、地图区名标签文本，以及标签白名单过滤（见第六节）                                   |
| `center`          | `[lng, lat]` | 区行政中心点经纬度（区政府驻地一带），**必然落在区内**                              | **备用**：标签定位的回退值，`centroid` 缺失时使用                                                             |
| `centroid`        | `[lng, lat]` | 多边形几何质心经纬度，按顶点平均计算                                                | **使用**：区名标签定位首选值。注意浦东、奉贤、崇明等区质心可能落在水域或半岛尖端，如需精确对位应回退 `center` |
| `childrenNum`     | `number`     | 下级行政区数量。区级无下级，恒为 `0`                                                | 未使用（溯源字段）                                                                                            |
| `level`           | `string`     | 行政层级，恒为 `"district"`（区/县）                                                | 未使用（溯源字段）                                                                                            |
| `parent`          | `Object`     | 上级行政区，`{ adcode: 310000 }` 即上海市                                           | 未使用（溯源字段，多城市扩展时可据此挂载到城市）                                                              |
| `subFeatureIndex` | `number`     | 该要素在原始数据中的序号（`0`–`15`）                                                | 未使用（渲染顺序由数组顺序决定）                                                                              |
| `acroutes`        | `number[]`   | 行政层级路径编码，`[100000, 310000]` 表示「中国 → 上海市」                          | 未使用（溯源字段）                                                                                            |

> `adcode` 不连续（如缺 `310103`、`310108`）是撤县并区的历史原因（卢湾并入黄浦、闸北并入静安），不是数据缺失。

## 五、geometry 结构

| 名称                                         | 类型             | 含义                                                                                                          |
| -------------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------- |
| `geometry.type`                              | `string`         | 恒为 `"MultiPolygon"`，一个区可能由多块互不相连的区域组成（岛屿、飞地）                                       |
| `geometry.coordinates[polygon][ring][point]` | `number[][][][]` | 四层嵌套：多边形 → 环 → 点 → `[经度, 纬度]`                                                                   |
| `coordinates[i][0]`                          | `ring`           | 外环，顺时针闭合边界，构成区的实体轮廓                                                                        |
| `coordinates[i][1..n]`                       | `ring[]`         | 内环（孔洞），通常为内陆水体，渲染时作为 `Shape.holes` 挖空。本数据各环数等于多边形数，即均为单外环、暂无孔洞 |

**坐标约定**：WGS84 经纬度，顺序为 `[经度, 纬度]`（与 GeoJSON 规范一致，**不是** 纬度在前）。经度东正、纬度北正，单位为度。

**渲染链路**（`City.jsx`）：每个环经 `projectShanghai` 转为场景平面坐标 → 生成 `Shape`（外环）/ `Path`（内环）→ `extrudeGeometry` 挤出 `0.65` 单位厚度 → 整组绕 X 轴旋转 `-90°` 平铺为地面。

**投影方式**（`features/scene/config/geography.js`）：等距圆柱近似，以 `MAP_CENTER = [121.5, 31.25]` 为原点，纬度每 1° 约 25 个场景单位，经度方向再乘 `cos(31.25°)` 修正。仅适用于上海市域范围，跨纬度大范围使用会失真。

## 七、修改约束

1. **加区/删区**：`city.districtCount` 自动跟随 `features.length`，但 `src/tests/modelData.test.js` 断言 `16` 与 `16`，需同步更新；`City.jsx` 的标签白名单也是硬编码区名，新增区默认不带标签。
2. **区名变更**：`properties.name` 同时用于标签文本与白名单匹配，两处需一起改。
3. **文件体积**：坐标点直接影响首屏包体（当前 3443 点），如需精简可降采样外环，但会牺牲轮廓精度；`centroid`/`center` 应保留，标签依赖它定位。
4. **不要改字段名**：`adcode`/`name`/`centroid` 已被渲染代码直接读取，重命名会静默失效（键不存在时标签不显示而非报错）。
